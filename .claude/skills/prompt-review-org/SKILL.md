# prompt-review-org スキル

Splunk Enterprise に蓄積された Claude Code セッションログから、組織全体のAI活用状況を分析し、
ユーザー別の技術理解度・プロンプティングパターン・AI依存度を推定してレポートを生成する。
レポートは日本語で `reports/prompt-review-org-YYYY-MM-DD.md` に書き出す。

## 前提

- Splunk Enterprise MCP (`mcp__splunk-mcp-server__splunk_run_query`) が利用可能であること
- `index=claude_code sourcetype="claude:session"` にデータが存在すること

## 引数の処理

`$ARGUMENTS` を解析し、以下のルールで引数を処理する:

- 数値のみ → **日数フィルタ**（例: `30` → 過去30日分）
- 文字列のみ → **ユーザー（host）フィルタ**（部分一致）
- 文字列 + 数値 → **ユーザーフィルタ** + **日数フィルタ**（例: `tanaka 30`）
- 引数なし → 全ユーザー、過去7日分（デフォルト）

引数から `earliest_time` を算出する:
- 日数指定あり → `-Nd`（例: 30日 → `-30d`）
- 日数指定なし → `-7d`（デフォルト）

## ステップ1: SPLクエリでデータ取得

[references/spl-queries.md](references/spl-queries.md) に定義されたSPLクエリを使用する。
`mcp__splunk-mcp-server__splunk_run_query` で実行し、`earliest_time` パラメータに算出した値を渡す。

### 1a. サマリー統計の取得

まず「サマリー統計クエリ」を実行して全体像を把握する。
ユーザーフィルタが指定されている場合は、クエリに `host="*<フィルタ値>*"` を追加する。

### 1b. プロジェクト別集計の取得

「プロジェクト別集計クエリ」を実行する。

### 1c. プロンプト本文の取得

「プロンプト本文取得クエリ」を実行して定性分析用のテキストデータを取得する。
`row_limit` は 200 を指定する。

**重要**: 結果が大きすぎる場合は、ユーザーごとに分割して取得する。

## ステップ2: 分析

取得したデータを以下の観点で分析する。各観点について**具体的なエビデンス**（実際のプロンプト断片の引用）を必ず含めること。

### 前処理: 短文応答の除外

以下のようなメッセージは分析対象から**除外**する:

- 単純な肯定: 「y」「yes」「はい」「うん」「ok」「sure」「yep」「yeah」
- 実行指示: 「進めて」「やって」「do it」「doit」「go」「go ahead」「proceed」
- 承認: 「それで」「それでいい」「それでお願いします」「お願いします」「いいよ」「いいです」「大丈夫」
- 感謝のみ: 「ありがとう」「ありがとうございます」「thanks」「thx」

**判定基準**: メッセージが短文（概ね20文字以下）で、上記のパターンに該当するもの。
ただし、短文でも具体的な技術指示を含むもの（例:「30pxがいいです」「asyncで」）は除外しない。

### 2a. 技術的理解度マップ（ユーザー別）

ユーザーごとにプロンプトから言及されている技術概念を抽出し、3段階に分類:
- **熟知**: 自信を持って指示、正確な用語使用、具体的な実装方針の提示
- **基本理解**: 概念は知っているが詳細はAIに委任
- **学習中/曖昧**: 質問形式、誤解がある、試行錯誤が多い

### 2b. プロンプティングパターン分析（ユーザー別）

- **効果的なパターン**: 具体的な制約指定、段階的な指示、十分なコンテキスト提供
- **改善可能なパターン**: 曖昧な指示、コンテキスト不足、目的と手段の混同
- **特徴的な癖**: 短い承認の頻度、日本語/英語の使い分け

### 2c. AI依存度分析（ユーザー別）

- ユーザーが方針を決定しAIに実装を任せているケース（主体的）
- AIに方針決定から任せているケース（依存的）
- デバッグ/エラー解決でAIに頼るパターン

### 2d. 組織横断の傾向

- 複数ユーザーに共通する強みパターン
- 複数ユーザーに共通する改善ポイント
- ユーザー間の活用レベルの差

### 2e. シークレット・クレデンシャル警告

プロンプト本文中にクレデンシャル（APIキー、トークン、パスワード等）が検出された場合、
レポートに警告セクションを出力する。

**レポート内ではシークレットの値は絶対に平文で書かない**。先頭数文字 + `***` でマスクする。

## ステップ3: レポート生成

[references/report-template-org.md](references/report-template-org.md) のテンプレートに従い、日本語でレポートを生成する。

### 出力ルール

1. `reports/` ディレクトリが存在しない場合は Bash で `mkdir -p reports` を実行
2. Write ツールを使って `reports/prompt-review-org-YYYY-MM-DD.md` に書き出す（YYYYMMDDは実行日）
3. レポート生成後、ファイルパスをユーザーに通知する

### 記述上の注意

- レポートは**必ず日本語**で出力すること
- 推測は「〜と推測されます」「〜の可能性があります」と明示すること
- プロンプトの原文を引用する場合は**短く切り取り**、プライバシーに配慮すること
  - ファイルパスの個人名部分は `<user>` にマスク
  - プロジェクト固有の機密情報は伏せる
- 分析できなかった部分は「データ不足のため分析できませんでした」と正直に記載
- エビデンスのないセクションは省略してよい
